沙盒与调试开关 ​

这一类参数会显著改变游戏体验，用途是方便调试、沙盒玩、或者快速体验内容。用之前请想清楚。

全部开关 ​

参数键默认说明
sandbox.timeScale1.0游戏时间缩放（0 = 暂停，1 = 原版，可快进/慢放）
sandbox.instantRepair0玩家舰船立即修好
sandbox.startRenown0新战役额外起始威望（千）
unlock.allShips0沙盒解锁全部内置舰级
local.versus0本地双人热座（关 AI）
debug.verbose0调试日志开关

sandbox.timeScale —— 全局时间缩放 ​

这是全框架最需要注意的参数

它控制游戏时间的流速，会影响所有按时间推进的东西：

  • 开火动画、装填动画
  • 舰船机动
  • AI 的行动
  • 场景转场、界面补间

所以把它调快，不只是「动画变快」—— 整个游戏节奏都会变。

值效果
0暂停（游戏冻结，像死机）
0.5慢放
1.0原版（默认）
2.0快进
3.0很快

最常见的困惑：「为什么点了发射就什么都没了」 ​

如果你把倍速调到 x3，然后按发射：

整个战斗推进会瞬间完成 —— 你会看到「点了发射，然后一瞬间就进了敌方回合」，感觉像点了发射后什么都没发生。

遇到这种情况怎么办

点悬浮窗上的倍速按钮，把它调回 x1。

悬浮窗旁边有个 x1 按钮，点一下循环 x1 → x2 → x3 → x1。倍速高于原速时按钮会有警示色，提醒你现在不是正常速度。

为什么倍速不保存 ​

这是一个刻意的设计

timeScale 只在本次运行有效。下次启动游戏，它会强制回到 1.0。

原因：如果它被存进设置文件，你下次打开游戏会发现「我明明什么都没调，怎么整个游戏都变快了/变慢了」，然后开始怀疑游戏坏了。

框架的选择是：宁可让你每次重新调，也不让你陷入「我不知道自己改过什么」的状态。

暂停档为什么不进快捷循环 ​

悬浮窗的倍速按钮循环是 x1 → x2 → x3 → x1，故意跳过了暂停档（0）。

原因：误触到暂停会让所有游戏协程冻结，看起来像死机，玩家第一反应是「游戏挂了」。所以不把它放在容易点到的循环里。

想用暂停，去「参数」页拖滑块。

sandbox.instantRepair —— 立即修理 ​

0 = 关闭，1 = 开启。

开启后，你的舰船修理时间为 0，等于随时修好，不用等。

和 repair.timeMul 的区别

参数效果
sandbox.instantRepair: 1完全立即修好（开关）
repair.timeMul: 0.5修理时间减半（倍率）
repair.timeMul: 0也等于立即修好

想要「稍微快点」用 repair.timeMul，想要「完全不要等」用 instantRepair。

sandbox.startRenown —— 开局威望 ​

创建新战役时额外给的威望，单位千。

值效果
0关闭
50多 5 万
100多 10 万

只对新战役生效

已有存档不会因此变化。要给现有存档加威望，用 存档页。

unlock.allShips —— 解锁全部舰级 ​

0 = 关闭，1 = 开启。

开启后，所有内置舰级都可用，不需要通过正常流程解锁。

适合「想直接体验所有船」

如果你只是想看看所有舰船长什么样、性能如何，开这个最省事。

但要注意：这会跳过游戏的解锁进度，如果你还在意「自己一点点解锁」的成就感，就别开。

local.versus —— 本地双人热座 ​

0 = 关闭，1 = 开启。

开启后，关闭 AI，两个人在同一台手机上轮流操作。

「热座」（Hot Seat）是什么意思

传统说法，指两个人共用同一台设备，一个玩完换另一个。因为设备会「热」，所以叫热座。

适合和朋友面对面轮流玩。

debug.verbose —— 调试日志 ​

0 = 关闭，1 = 开启。

开启后，框架会写更详细的日志（每一步加载、每一次参数读取）。

只在排查问题时开

调试日志量很大，会让 AFMOD_log.txt 迅速变大（虽然有 200 KB 上限自动截断）。

出问题时让作者让你开，平时关着就行。

仔细看每一步sandbox.timeScale = 0.5
