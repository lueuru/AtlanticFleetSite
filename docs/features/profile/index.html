玩家档案与本地热座 ​

本篇讲框架的玩家档案 和本地热座对战能力。

先说清楚一件事

这个游戏没有联网对战，框架也没有加入联网对战。

框架提供的是：

  • 玩家档案（记录你是谁、造过什么）
  • 本地热座对战（同一台手机，两人轮流玩）

真·联网对战不在能力范围内（原因见下文）。

玩家档案（账号） ​

它是什么 ​

一个存在本地的身份档案，记录：

  • 你的代号（handle）
  • 累计威望
  • 造过的舰船数
  • 以及作为你分享出去 Mod 的署名

纯客户端环境下，「账号」就是这个意思

游戏没有服务器，所以没法做真正的账号系统。

框架的做法是：一份存在游戏私有目录里的本地档案 —— 它让 Mod 能记住「你是谁、做过什么」，并作为你创作内容的署名。

这对「离线换创作」这个玩法来说，已经够了。

存在哪 ​

Android/data/<游戏包名>/files/mods/AFMOD_profile.json
1

为什么放在 mods/ 里

因为方便管理，而且框架扫描 Mod 时只扫子目录里的 mod.json，不会把这个档案误当成 Mod 读取。

代号从哪来 ​

优先顺序：

  1. mod.json 顶层的 handle 字段（如果你写了）
  2. 档案里已保存的 handle
  3. 都没有 → 显示默认值「指挥官」

档案记录什么 ​

内容说明
累计威望每次结算获奖都累加（天然不重复计数）
自制舰数当前启用的自制舰数量（每次加载覆盖，不是累计）

本地热座对战 ​

怎么开 ​

「参数」页 → 找到 local.versus → 设为 1。

开启后：关闭 AI，两个人轮流用同一台手机操作。

什么是「热座」 ​

Hot Seat，传统说法。指两个人共用同一台设备，一个玩完换另一个。因为设备会「热」，所以叫热座。

适合什么场景 ​

  • 和朋友面对面轮流玩
  • 想纯人对战，不要 AI 掺和
  • 手机上solo练习时，用它来双方对照测试自己的 Mod 效果

一个实用技巧

如果你想测试「我改的参数到底有多大影响」，开热座模式，自己控制双方，就能直接对比。

比反复打 AI 更快得出结论。

为什么不做联网对战 ​

这是一个明确的能力边界

原因有三层：

  1. 游戏本体没有网络栈 —— 游戏是纯单机的，没有可以复用的网络层。
  2. 要新加整个网络体系 —— 在 Unity 4.7 / 老 Mono 上引入 HTTP、TLS、超时重试、断线重连，风险很高。
  3. 无法验证 —— 没有真机测试条件，网络功能只能做到「编译通过」，不能保证真的能用。

一个「编译通过但从没跑通过」的联网功能，比不做更糟。

所以框架把「交换创作」这个真正有价值的玩法做扎实了（分享码 + 在线仓库），而不是去碰做不到的联网对战。
