Mod 冲突排查 ​

多个 Mod 之间可能互相干扰。本篇讲清楚什么算冲突、怎么查、怎么解决。

先明确：冲突不是错误 ​

重要心态

冲突是「可预期的正常现象」，不是 bug。

框架处理冲突的方式是：

  • 记录一条告警
  • 后加载的覆盖先加载的
  • 游戏照常运行

所以看到冲突告警不用慌 —— 游戏没有坏，只是有一个 Mod 的改动被另一个盖住了。

三类冲突 ​

框架会检测三种冲突：

类型什么情况后果
参数键冲突两个 Mod 改了同一个参数后加载的覆盖前者
舰级重名两个 Mod 定义了同名舰级后加载的覆盖前者
编队重名两个 Mod 定义了同名编队后加载的覆盖前者

怎么发现冲突 ​

位置一：Mod 页顶部横幅 ​

如果有冲突，「Mod」页顶部会出现：

检测到 3 处 Mod 间重名冲突
1

位置二：日志页筛选「告警」 ​

日志里会有具体内容，比如：

[告警] 参数 [combat.gun.damageMul] 在 Mod [强化主炮] 与 [超级火力] 间重名，用后加载的 [超级火力] 覆盖
[告警] 舰级 [曙光级] 在 Mod [A] 与 [B] 间重名，用后加载的 [B] 覆盖
1
2

「告警」级别就是这个用途

冲突全部记为告警级（橙色），所以在日志页点「告警」筛选，冲突一目了然。

详见 日志页：自查问题。

谁覆盖谁 ​

规则是：按加载顺序，后加载的覆盖先加载的。

加载顺序由 priority 字段决定：

priority效果
数值小先加载（会被覆盖）
数值大后加载（会覆盖别人）
相同按名字排序（保证可复现）

举例

Mod A：priority: 10 Mod B：priority: 20

加载顺序：A → B。 所以 B 的取值生效，A 的被覆盖。

怎么解决冲突 ​

有四种做法，按推荐程度排列：

做法一：改名字（最干净） ​

如果是舰级或编队重名，直接改掉其中一个的名字。

json
// Mod A
"class": "曙光级"

// Mod B —— 改成不一样的名字
"class": "晨光级"
1
2
3
4
5

推荐这个 —— 两个 Mod 都能正常用，没有覆盖。

做法二：用 priority 控制顺序 ​

如果是参数冲突，而且你确实想两个都留着，就用 priority 明确谁生效：

json
// 想让这个 Mod 的改动生效，给它更高的 priority
"priority": 100
1
2

做法三：禁用其中一个 ​

如果两个 Mod 功能重复，其实只需要一个：

「Mod」页 → 禁用不要的那个。

做法四：合并成一个 Mod ​

如果两个 Mod 你都想要，而且冲突的部分本来就应该统一，那就手动合并成一份 mod.json。

结果：

参数谁生效最终值
combat.gun.damageMul「平衡调整」（priority 20 后加载）1.2
combat.torpedo.damageMul「强化火力」（只有它改了）1.5

并且日志会记一条告警：参数 combat.gun.damageMul 在两个 Mod 间重名。

这就是「明明显式写了 2.0 却是 1.2」的原因

如果你只看「强化火力」的配置，会以为主炮伤害是 2.0。

但因为「平衡调整」后加载，实际生效的是 1.2。

所以：遇到「数值和我写的不一样」，第一件事就是查冲突。

怎么确认「实际生效的值是多少」 ​

两个地方：

  1. 状态页 → 偏离清单显示的是实际生效值（不是某个 Mod 里写的心愿值）
  2. 日志页 → 告警行会写明谁覆盖谁

为什么设计成「只告警不阻止」 ​

设计理由

玩家写错配置不应该导致游戏打不开。

如果框架遇到冲突就报错退出，那么一个小的配置错误就会让玩家完全无法进入游戏 —— 而且可能不知道是哪个 Mod 的问题。

所以框架的选择是：

做法结果
冲突就阻止加载一个错误配置 = 游戏打不开
冲突只告警（框架选择）游戏照常跑，冲突可复现、可查、可撤销

在「严格」和「可用」之间，框架选了可用。

常见问题 ​

冲突横幅显示的数字一直不变 ​

它统计的是当前探测到的冲突数。禁用掉冲突的 Mod 后（重开游戏）数字会变。

我只有一个 Mod，怎么还有冲突 ​

可能的原因：

  1. 这个 Mod 内部有重复定义（同一个参数在文件里写了两次）
  2. 和你自己的参数改动冲突 —— 参数页改的值也会参与

告警太多，看不清 ​

用日志页的筛选取「告警」，然后从头一条条看。通常真正的冲突就那几条。

冲突会导致游戏崩溃吗 ​

不会。 冲突只影响「哪个值生效」，不影响游戏运行。

如果游戏真的崩了，那是另一个问题 —— 去 出问题了怎么查。
