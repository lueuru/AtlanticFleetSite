首次启动与目录 ​

首次启动游戏时，框架会自动在手机上建立一套目录。本篇说明这些文件是什么、能不能删、出问题去哪找。

框架建了什么 ​

启动游戏后，框架在你的数据目录下建立这些内容：

Android/data/<游戏包名>/files/
├── mods/                          ← Mod 存放目录
│   ├── _示例Mod_可删除/            ← 自动生成的示例，教你格式
│   │   └── mod.json
│   └── <你自己加的 Mod>/
│       └── mod.json
├── AFMOD_settings.json            ← 面板设置（位置、展开状态）
├── AFMOD_log.txt                  ← 运行日志
└── rncampaignInfo.dat             ← 游戏原有存档（框架不动它）

逐个说明 ​

mods/ 目录 ​

框架扫描 Mod 的地方。 规则：

  • 每个 Mod 是 mods/ 下的一个子文件夹。
  • 文件夹里必须有 mod.json。
  • 不能直接把 mod.json 丢在 mods/ 根目录（框架不会读）。

正确的：

mods/
├── 我的强化主炮/
│   └── mod.json       ✅ 子文件夹里，能读到
└── 悠闲模式/
    └── mod.json       ✅

文件夹叫什么名字都行

框架读的是 mod.json 里的 modName 字段，文件夹名只用于区分和管理（比如禁用时会生成 文件夹名_disabled.txt）。所以用中文名也没问题。

_示例Mod_可删除/ ​

首次启动自动生成的示例 Mod，里面是一个带注释的 mod.json，演示了各种字段怎么写。

  • 可以直接删掉，不影响框架运行。
  • 建议先看一眼内容再删，格式就懂了。

以 _ 开头的文件夹框架会特殊处理，不会被当成正常 Mod 加载。

AFMOD_settings.json ​

面板自身的设置，比如：

  • 悬浮窗的位置（你拖到哪，下次还在哪）
  • 各个参数分组是否展开
  • 上次停留在哪个页面

悬浮窗位置存了版本号

如果框架升级导致界面布局变化，旧位置可能不合适（比如压到新按钮上）。这时设置文件里会有一个版本号字段，框架检测到版本不符会重置到安全位置。所以你不用手动改这个文件。

AFMOD_log.txt ​

运行日志。框架把加载了哪些 Mod、改了哪些参数、有没有冲突、引擎有没有报错，都写在这里。

  • 游戏内「日志」页可以直接看，也能一键导出。
  • 排查问题的第一现场，详见 日志页：自查问题。

为什么日志要落盘

因为只存内存的日志，游戏一关就没了。真机上遇到问题想找人帮忙看，没有文件就没有证据。所以框架的日志策略是：累积到一定条数写一次磁盘，退出时补刷，超过 200 KB 自动截断保留最近的。

找不到目录怎么办 ​

Android/data 在安卓 11+ 被系统限制了访问，常见表现是「文件夹是空的」或「打不开」。

解决办法：

  • 推荐：用 MT管理器（申请了对应权限，能进 Android/data）。
  • 或者用数据线连电脑访问。
  • 或者根本不进目录 —— 框架提供了完整的面板操作，装 Mod 可以直接粘贴分享码，看日志可以在游戏内看。详见 安装 Mod 的三种方式。

清理建议 ​

想清理的话，各文件的处理方式：

文件能删吗后果
mods/<某Mod>/✅ 能那个 Mod 失效（也可以在面板里禁用，更安全）
_示例Mod_可删除/✅ 能无影响
AFMOD_settings.json✅ 能面板设置重置（位置回到默认、展开状态清空）
AFMOD_log.txt✅ 能历史日志丢失（会重新开始写）
rncampaignInfo.dat❌ 别删这是游戏存档，删了进度就没了

框架不会碰游戏存档文件

框架要改存档时，是通过游戏自己的保存接口，而不是直接改这个文件。所以除了你自己手动删，这个文件不会被框架动到。
