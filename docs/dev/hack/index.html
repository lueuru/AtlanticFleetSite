如何修改框架本身 ​

想加一个新参数、加一个新挂钩、或者改面板界面？这一页讲在哪里动手，以及必须遵守的铁律。

先理解设计原则 ​

整个框架有两条贯穿始终的原则，改任何东西前先记住：

原则一：原版值 × 倍率

参数改的不是「伤害 = 100」，而是「伤害 = 原值 × 倍率」。这样：

  • 倍率是 1.0 时，与原版逐字节等价
  • 不同舰船 / 武器的原始差异全部保留
  • 游戏更新后参数不会失效

原则二：任何异常绝不阻断游戏

所有文件读写、模型加载、参数应用都包在 try/catch 里。出错只记一条日志，绝不让游戏或启动崩掉。

玩家写错配置不该导致游戏打不开。

场景一：加一个新参数 ​

三步。

1. 在 ModConfig.cs 注册 ​

在参数表里加一行（注意 C# 3.0 语法，用 1f 不是 1.0f 也行，但要与现有一致）：

csharp
new ParamDef("gun.burstMul", 1f, 0.5f, 2f, 0f, 5f, "主炮连发倍率"),
1

参数：(key, 默认值, 软下限, 软上限, 硬下限, 硬上限, 中文说明)。

2. 加一个取值的钩子方法 ​

在 TuningHooks（门面类）里加：

csharp
public static float GunBurst() { return Get("gun.burstMul"); }
1

Get 未注册的键会返回 1.0（安全默认），所以不用怕拼错键导致伤害归零。

3. 在游戏源码的实际计算点挂钩 ​

找到那个「原版值」算出来的位置，乘上倍率：

csharp
// 原版：
num = baseDamage;
// 改后：
num = baseDamage * TuningHooks.GunBurst();
1

3
4

只放大基数，不要动随机序列

原版伤害计算里常有 num *= Random.Range(0.8f, 1.2f) 这类随机散布。倍率要乘在随机之前的基数上，不要去改随机范围的上下限——那会破坏原版的分布。

编译通过 = 挂钩绑定成功（方法名写错会报 CS0103）。

场景二：加一个一次性注入（像 unlock.allShips） ​

如果某个功能是「找到某个对象后执行一次」，而不是「每次计算时乘倍率」：

  1. 在 ModRuntime.cs 的 Update() 里加侦测逻辑（找 Database 等对象）。
  2. 找到后执行注入，包在 try 块内。
  3. 用一个 bool 标记「已执行」，避免每帧重复。
  4. 纯数值赋值、不改数组长度。

场景三：改面板界面 ​

面板全在 ModPanel.cs，6 个标签页：参数 / Mod / 存档 / 日志 / 状态 / 帮助。

铁律（全是踩坑换来的） ​

面板工程六条铁律

  1. 临时改 GUI.skin 必须成对还原。在方法开头改了字号/按钮高/滑块把手，方法结尾一定要改回去，否则会永久污染全局界面（连悬浮窗小按钮都会变大）。
  2. 每个标签页都必须有 BeginScrollView。内容随版本增长必然溢出，溢出就是「看不见又滚不动」的死内容。
  3. 破坏性按钮（恢复默认 / 删除）一律两段确认，且确认态要在切页和开关面板时清零，防残留误点。
  4. 桌面鼠标尺度的默认值不适用于手机：字号 16、按钮高 38、滑块把手 36 才够手指用。
  5. 绝不加「长按 N 秒才响应」门槛。这会让玩家完全打不开面板且毫无提示。防误触只能靠「位置远离操作区 + 点窗外收起」。
  6. 点击/拖动位移阈值要按屏宽比例取：TapSlop() = max(12, 屏宽*2%)。固定 6px 在手机上必被抖动突破。

触控目标最小 ~44px ​

视觉上可以画小，但判定区必须外扩（视觉 34px → 判定 54px）。主按钮尤其要注意别与相邻按钮抢点击。

必须留一条「事件收不到」的逃生通道 ​

部分 Android 抬手时 OnGUI 收不到 MouseUp。所以：

  • 加超时兜底：按下 0.45s 未发生位移就按点击处理（用 realtimeSinceStartup，不用 Time.time，暂停时不卡）
  • 加三指同按屏幕强制唤起（走 Input.touches，完全不依赖 OnGUI 事件）

场景四：加一个新的挂载点 ​

框架的启动顺序在 ModBridge.Init()。想看流程从那里读：

ModBridge.Init()
  → ModProfile.Load()        // 加载玩家档案
  → ModConfig 初始化          // 参数表 + 读覆盖层
  → ModLoader.LoadAll()      // 扫 mods/、解析、注入
  → ModPanel / ModRuntime     // 界面与运行时驱动

加东西尽量挂在既有环节末尾，不要打乱顺序——顺序错了会出现「参数没读到就注入」这类隐蔽 bug。

改完必须做的三件事 ​

  1. 编译（python compile.py）→ 退出码 0
  2. 核对汉化无损（补丁脚本会打印条数，正常 213 条）
  3. 确认定版 APK 未被改动
