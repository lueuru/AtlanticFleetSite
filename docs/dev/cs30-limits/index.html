C# 3.0 兼容约束 ​

框架的目标运行时是 Unity 4.7（2015 年）/ Mono / .NET 3.5，编译器只认 C# 3.0 语法。写新代码前必读这一页——用错语法会直接编译失败。

禁用清单 ​

特性版本说明替代方案
默认参数 void F(int x = 0)C# 4❌ 禁用重载一个同名方法
可选参数 / 命名参数C# 4❌ 禁用用重载
dynamic 类型C# 4❌ 禁用用 object + 显式转换
?. 空条件运算符C# 6❌ 禁用if (x != null) x.Y
$"..." 字符串插值C# 6❌ 禁用string.Format(...) 或 + 拼接
表达式体成员 => x;C# 6❌ 禁用写完整方法体
内联 out varC# 7❌ 禁用先声明变量再 out
元组 (int, int)C# 7❌ 禁用用 out 参数或小结构体
模式匹配 is int iC# 7❌ 禁用is + 显式转换
局部函数C# 7❌ 禁用独立私有方法
switch 表达式C# 8❌ 禁用传统 switch 语句
using 声明（无花括号）C# 8❌ 禁用传统 using { } 块
nameofC# 6⚠️ 慎用视编译器而定，宁可用字符串字面量

可以放心用的 ​

C# 3.0 本身已经够用：

  • ✅ var（隐式类型，C# 3）
  • ✅ 对象 / 集合初始化器（完整写法：new Foo { A = 1 }）
  • ✅ LINQ to Objects
  • ✅ 扩展方法
  • ✅ Lambda 表达式
  • ✅ 自动属性 public int X { get; set; }
  • ✅ 匿名类型

// ✅ 用重载代替（C# 3）

为什么这么严格 ​

用高版本语法 = 编译直接失败

C# 编译器遇到不认识的语法会立即报错（CSxxxx 系列），不是警告。所以宁可保守。

另外要注意：本工程的 Assembly-CSharp.csproj 里还有一些框架内嵌的兼容写法（如 MiniJson），改动它们时保持同样风格。

一个反面教材 ​

开发中确实踩过这个坑：给方法加了个 = null 默认参数，编译器报错，排查了一阵才发现是语法版本问题。所以「加参数」这件事在 C# 3.0 里永远要写成一个新重载。
