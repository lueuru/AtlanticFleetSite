开发总览 ​

这一章是给想自己写 Mod、或者想改框架本身的人看的。如果你只是想玩游戏、用别人做的 Mod，看完前面的「安装部署 / 功能接入 / 使用指南」就够了。

两条路：写 Mod，还是改框架 ​

请先分清你要做哪件事，因为难度差别很大：

写一个 Mod改框架本身
你要做什么新建文件夹 + 写一个 mod.json改 C# 源码 → 重编译 DLL → 重打包 APK
需要工具记事本就够了Visual Studio / Mono + Python + 签名工具
需要懂编程吗完全不需要需要（C# 3.0）
影响范围只影响你自己的游戏影响整个框架、所有玩家
从哪开始mod.json 完整规范框架源码结构

绝大多数人只需要左边那一列

框架的设计目标就是「不写一行代码也能做出舰船、编队、改数值、换模型」。真正要动 C# 的场景很少。

这一章包含什么 ​

  • mod.json 完整规范 —— 一个 Mod 文件里所有字段的权威字典
  • 参数键全表 —— 23 个可调参数的键名 / 默认值 / 边界 / 含义
  • 舰船与编队定义 —— ships[] 和 fleets[] 的每个字段
  • 制作 AssetBundle 模型 —— 用 Unity 导出能用的模型包
  • 发布你的 Mod 到仓库 —— 让别人一键装上你的作品
  • 框架源码结构 —— 100 个源文件都是干嘛的
  • 编译环境搭建 —— 从零把编译链跑起来
  • C# 3.0 兼容约束 —— 写代码前必读的「不能用什么」
  • 如何修改框架本身 —— 挂钩点在哪、怎么加新功能
  • 调试与日志接口 —— ModLog / 探针 / 落盘机制
  • 贡献与规范 —— 怎么把改动合回来

一个最重要的前提 ​

改完必须重开游戏

框架在游戏启动时扫描一次 Mod 目录、读一次参数。运行中改文件不会生效。所有「改了没反应」的问题，第一步都是完全退出游戏再重开。

  • 想直接抄一个 → 快速开始
  • 要改框架 → 编译环境搭建
