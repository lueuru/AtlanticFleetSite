贡献与规范 ​

这个框架是个人项目，但欢迎提改进、报问题、贡献 Mod。这一页讲改动应该遵守什么规范。

提交改动前，先自检 ​

五条必过

  1. 编译通过（python compile.py 退出码 0）——这同时证明挂钩绑定成功
  2. 汉化无损——补丁后条数不变（正常 213 条）
  3. 定版 APK 未被改动——final_full_cn.apk 是汉化定版，框架与它完全隔离
  4. 语法合规——只用 C# 3.0（见 兼容约束）
  5. 异常兜底——新增可能抛异常的代码都包了 try/catch

代码规范 ​

命名 ​

类型约定例子
框架类Mod 前缀ModConfig / ModLoader
参数键组.动作 小写点分gun.damageMul
常量大写下划线PREFIX / IMPORT_DIR
私有字段下划线前缀（按现有风格）_overrides

铁律清单（每条都是踩坑换来的） ​

#铁律为什么
1参数持久化：实验性/危险参数绝不跨会话保存尤其 sandbox.timeScale，否则玩家陷入「我什么都没调却全变了」
2倍速暂停档绝不进快捷循环误触到 x0 会让全部协程冻结，像死机
3改 GUI.skin 必须成对还原否则永久污染全局界面
4每个标签页都要 BeginScrollView内容必然溢出，溢出即「看不见又滚不动」
5破坏性按钮两段确认，确认态要清零防残留误点
6触控判定阈值按屏宽比例取固定像素在手机上必被抖动突破
7诊断日志必须落盘内存日志游戏一关就没了
8成组预设值必须机器校验边界超硬边界会被静默钳制，最难查

贡献 Mod 的规范 ​

比贡献代码更常见、也更值得做的事：做一个 Mod 分享出来。

质量要求 ​

项要求
modName必需，写清楚是什么
author建议填，方便别人找你
version建议填，便于追踪
参数值别超硬边界（对照 参数键全表）
舰级 / 编队名起不重复的名字，避免与他人冲突

发布到仓库 ​

打开 Mod 仓库 的上传区，填作者、拖入（或粘贴）mod.json，点「提交审核」。管理员过审后自动上架。

详细步骤见 上传你的 Mod（作者）。

报告问题 ​

报问题时，日志是关键证据。请附上：

  1. 游戏内「小u」→「日志」页 →「复制全部日志」的完整内容
  2. 你的设备信息（日志里已含：屏幕 / DPI / 系统版本 / 内存）
  3. 复现步骤（做了什么、期望什么、实际什么）
  4. 装了哪些 Mod（如有）

不要只贴现象

「打不开」「没反应」这类描述定位不了问题。日志里的一行错误码，比十句现象描述都有用。

已知限制（不要当 bug 报的） ​

限制说明
不支持互联网联机受纯客户端重编译约束，只能同设备热座
无 Harmony有意不做，用源码内挂钩（见 路线图）
游戏内无 Mod 市场有意不做，用网页版仓库替代
真机兼容矩阵需真实设备，本机无模拟器，靠设备自检 + 回传
