网站改版（v3.0 → v4.8） ​

这一节记的是网站本身的改进。上面 v2.x 记的是游戏内框架的版本，两者是并行的两条线。

最近一轮集中处理了可读性、移动端与安全：

  • 对比度全站达标：正文与所有小字（卡片副标题、分类标签、代码块语言名）按无障碍标准（正文 4.5:1）逐项核算，深浅两套主题都验过
  • 术语统一：「悬浮球 / 悬浮窗」「声望 / 威望」「游戏里 / 游戏内」各归一处，读者不会再看到同一个东西两种叫法
  • 手机端适配：顶栏、卡片、页脚、触控目标（最小 44px）逐项重做；代码块与表格在窄屏改为容器内横向滚动，不再撑破屏幕
  • 平板断点修复：768~959px 下顶栏不再把页面撑出横向滚动条
  • 悬浮窗遮挡修复：右下角的日/夜切换按钮改为阅读时自动让路
  • 安全加固：管理员密钥改用防时序攻击的比较方式、上传接口加频率限制、跨域收紧为同源、加防点击劫持响应头
  • 性能：鼠标悬停效果改到逐帧计算（消除强制同步布局），移动端毛玻璃降级为半透明底色，字体子集化
  • 稳定性：API 服务常驻（开机自启 + 崩溃自愈），仓库页在服务不可用时回退到本地存档，不再整页空白

v2.19 — 网页上传 + 审核后台 ​

把「作者要跑命令行才能发布」彻底改成「在网页上填个表就能传」，并给站长配了审核后台。

  • ★ 网页上传机制：仓库页新增上传区，拖入 / 粘贴 mod.json → 填作者 → 提交审核。不再需要命令行脚本
  • ★ 审核后台（/admin/）：密钥登录，看四个指标（待审核 / 仓库在架 / 仓库总量 / 已驳回），逐条「通过并上架 / 驳回 / 下架 / 删除」，全程写操作日志
  • ★ 后端服务：零依赖 Python 脚本（只用标准库 + SQLite 单文件），负责收上传、校验、生成分享码、重建仓库清单
  • ★ 分享码解析器：网页上粘贴陌生 AFMOD1: 码，立刻显示这是哪个 Mod、谁写的、改了哪些参数（真的做出来了，此前文档里承诺但没实现）
  • 修掉「已上架」数字虚高：「已上架」口径改为以 packages/ 目录为准，手工删包后后台与仓库不再对不上
  • 修掉「参数条目」永远显示 0：接口此前只认 params 字段，而真实 mod.json 用的是 combat 嵌套结构；现在会把 combat.torpedo.accuracyMul 这类正确展平统计
  • 示例 Mod 全面重做：原来 3 个是空壳（没有舰船 / 舰队），替换为重做后的 6 个主题 Mod（铁底湾 / 狼群 / 决斗 / 夜雾 / 沙盒 / 雷雨），每个都有完整参数 + 自定义舰船 + 自定义编队，并配了分享码
  • 视觉全面升级：海战军工风设计系统（毛玻璃、雷达扫描、光效动画），仓库页 / 后台 / 文档站统一
  • 后端以计划任务常驻（SYSTEM 身份 + 开机自启 + 崩溃自愈），不依赖手动启动

v2.18 — 服务器版 Mod 仓库 ​

把 Mod 分享做到「网页浏览 + 分享码导入」，不碰游戏内代码。

  • 仓库站点：纯静态网页（网页 + 清单 + 可下载包），对外以 http://<站点地址>/mods/ 形式提供
  • 发布工具 publish_repo.py：一条命令上架，自动生成清单、包、分享码（已被 v2.19 的网页上传取代）
  • 网页功能：搜索 / 排序 / 详情弹层（自动列出「改了哪些参数」）/ 一键复制分享码
  • 修掉一个会让玩家下错包的真 bug：中文名 Mod 的 ASCII 别名全部退化成同一个 mod，导致互相覆盖。改为用名字哈希生成唯一别名，并加了发布前清空 packages\
  • 纯周边：不改游戏内代码

v2.17 — 存档编辑页 + 自制模型检查 ​

回应审查里五项，逐项处置：

  • 新增「存档」标签页：给进行中的战役改威望（±1千/1万，一键设 10万/50万/100万/满）和回合（±1/±10）。改的是运行时字段，保存时调用游戏自带的存档 Save()，绝不手改二进制
  • 「跨游戏资源移植」改为「自制模型检查」：不做跨游戏扒资源（版权风险），改为列出所有已登记模型包的自检结果（在不在 / 加载成功没 / 多大）
  • Harmony / Mod 浏览器 / 兼容矩阵 → 写入 路线图
  • 标签页变为 参数 / Mod / 存档 / 日志 / 状态 / 帮助

v2.7 — 倍速不再跨重启保留 ​

真机反馈：「总感觉什么速率都变快了」。

根因：sandbox.timeScale 被落盘持久化，重启仍是 x2/x3，而 Time.timeScale 管辖一切时间推进。

修复：启动强制回 x1（仅本次会话有效）；状态页加「偏离原版的参数」清单。

v2.6 — 悬浮窗点不动修复 ​

真机反馈：「最小化后打不开、点不动」。四个根因一次全修：

  1. 删掉「长按 0.3 秒」门槛（恢复点按即开）
  2. 位移阈值 TapSlop() 按屏宽 2% 取（不再用鼠标的 6px）
  3. 圆点放大到 34px 且判定区外扩
  4. MouseUp 超时兜底 + 三指手势强开

点击判定状态机 10/10 单测通过。

v2.5 — 「状态」页探针 ​

新增「状态」标签页，每 0.5 秒读战斗现场（回合 / 是否玩家回合 / 主炮装填门数 / 鱼雷装填管数 / 倍速），不再靠猜。

v2.4 — 排查「点发射后什么都没了」 ​

排除式排查：排除汉化误译、排除伤害倍率归零、排除日志回调冲突。

新增 ModLogHook.cs：Unity 引擎 Error/Exception/Assert 自动进日志页，异常风暴限流。

v2.3 — 真机反馈修复 ​

  1. 悬浮窗默认位置从右下角改顶部居中（原位置压住战斗射击按钮）
  2. 倍速循环去掉暂停档（误触 x0 会让所有协程冻结像死机）；timeScale 为 0 时按钮变红警示
  3. 加「长按 0.3 秒防误触」门槛、面板真悬浮窗化（点外收起、标题栏拖动）、参数行中文化

    ⚠️ 长按门槛在 v2.6 被移除——它导致玩家完全打不开面板

★ 作者自我更正 ​

保留在此，便于后人少走弯路。

① 「主炮按轮装填」—— 作废 ​

曾写过：「主炮装填按轮计，所以第 2 轮点发射没反应」。

正确规则：主炮每回合都可以炮击，只有鱼雷才每回合装填一发（turnsToReload 只对鱼雷生效）。

所以「第 2 轮打不出去」不是机制，是真缺陷。

② 「悬浮窗吞点击」—— 解释不成立 ​

曾推测：悬浮窗挡住了射击按钮导致点不动。

源码核查：战斗 UI 走 NGUI，用 Input.GetMouseButton* / Input.touchCount 轮询，不依赖 OnGUI 的 Event.current。所以在悬浮窗里调 e.Use() 拦不住 NGUI 按钮——两者是两套独立输入管线。

结论：把悬浮窗挪到顶部仍有价值（视觉上不再盖住按钮），但不是「点射击没反应」的修复。

该现象的真因嫌疑是 x3 倍速时的时序问题（开火/装填/动画都 3 倍速推进，玩家没看清就进了敌方回合，观感正是「点了发射后什么都没了」）。

这也正是 v2.7 把倍速改成「仅本次会话有效」的背景。
